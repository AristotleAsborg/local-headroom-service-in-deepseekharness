1.1.1（2026-09-11）
--------------------------------------------------------------------------------

修复一个会让新建会话全部失败的安装残留：早期版本留下的默认 agent preset 指向了已
经被删除的 preset。只动了 install.mjs，插件本体（plugin/index.js、
plugin/lib/engine.js）与工具契约没有 任何改动。

症状

Web 界面里新建对话、选中一个工作区之后，选择立刻弹回未选择状态，对话建不起来；重
试同样失败。

根因

首版除了 host row 之外还装过一个同名 agent preset，后来退役了——preset 在自身
scope 注册工具、 host row 在全局注册，tools.register() 对重名直接抛错，选中它会
失败。但用户设置文件里那条默认值 还指着它：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
agent-presets:
  default: headroom
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

默认 preset 是会话未显式选择时的解析目标。harness 自己的 AgentPresets.remove()
删除 preset 时 会顺手清掉指向它的默认值，正是为了避免这种悬空状态；而安装器是直
接删目录，没有调用 remove()， 于是留下了这一条。这条链路是：

1. 界面乐观地把工作区标为已选中，随即调用 sessions.create({ workspaceId })；
2. 会话不存在显式 preset，于是解析默认值 headroom；
3. AgentPresets.resolve() 找不到它，抛 agent-preset/not-found；
4. 创建被拒，界面把那个乐观选中撤回——现象就是"选择后弹回未选择"。

修复

install.mjs 在退役 preset 目录的同时清掉指向它的用户默认值：

- 删掉 agent-presets: 段里那一行 default: headroom；
- 该段还有别的条目就保留段头，一条都不剩就整段移除（不留 agent-presets: {} 这种
  等价但更含糊的写法）；
- --dry-run 只报告不写盘，重复运行不会重复报告，也不改无关的排版。

顺带修掉的一处：从别的目录启动时误跳过一轮测试

独立发布包里的 install.mjs 用 node "…\headroom-package\install.mjs" 这样从别的目
录启动时， verify.mjs 会被误判成"不存在"而报 skip——那套测试明明在包里。原因是存
在性检查按启动目录 解析，而子进程按脚本目录启动，两者不一致。现在两处都按脚本目
录解析，测试不会再被静默跳过。

升级与手动修复

跑一次 node install.mjs（或用独立发布包 headroom-package/ 里那一份）即可修好已受
影响的部署， 默认 preset 回落到随包默认的 standard。不必重启：harness 对
settings.yaml 有文件监听与热重载。

不想跑安装器的话，手动删掉 settings.yaml 里那一行 default: headroom 效果相同。

这件事的两条教训

- 退役一个东西，要连指向它的引用一起退役。 删除目录只做了一半，悬空的引用才是故
  障本身。
- 插件本身没问题，是安装器留下的状态有问题。 排查时先看部署状态里有没有指向不存
  在对象的配置，
  再看插件代码。
